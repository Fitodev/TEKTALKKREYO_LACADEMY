# Guide de style pédagogique

L'interface et tous les contenus destinés aux élèves sont en créole haïtien naturel, langue HTML `ht`. Les noms de produits et API restent inchangés. Les documents d'ingénierie peuvent être en français.

Chaque leçon doit comprendre 3–5 objectifs, prérequis, 800–1200 mots utiles (avec ajustement motivé pour les démonstrations de code), 5–8 sections, exemples de petite entreprise fictive, démonstration et résultats attendus, trois erreurs et corrections, vidéo vérifiée ou « Videyo ap vini », cinq questions spécifiques avec explications privées, devoir à barème 100, solution modèle privée, outils officiels, résumé et suite.

La fiche de sujet importée ne constitue pas une leçon. Ne pas reproduire les mêmes questions génériques pour les quarante leçons. Les questions d'application et de cas pratique nécessitent une grille d'évaluation ; ne pas garantir une correction automatique.

Pas de clients réels, de prix inventés, de promesses de gratuité universelle ou de vidéos fictives. Une ressource étrangère doit indiquer sa langue et avoir un résumé fidèle en créole. Aucun lien affilié n'est nécessaire pour réussir.

Cycle : rédaction → contrôle pédagogique → relecture par une personne maîtrisant le créole haïtien → vérification des sources et droits → tests → publication admin. Conserver la date et l'identité de relecture dans le futur CMS. Une validation automatique ne remplace pas cette revue.
